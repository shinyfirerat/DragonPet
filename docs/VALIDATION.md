## 在第二台 Mac 上怎样知道能运行

1. 获取干净源码，执行 `./build.sh` 与 `./scripts/test.sh`，记录 macOS、架构、Swift 版本和结果。
2. 将应用放入“应用程序”，以无个人配置启动；不安装 DSH/Codex/CodexBar时，应仍显示角色、支持按压/拖动/音效，并能打开设置和退出。
3. 接入自己的一个模型，测试一句；等待中连点不应发多请求；切换来源、关闭气泡、断网、错误模型都应能恢复。
4. 安装并登录 CodexBar，读取来源列表，选两项，检查名称/排序/隐藏，失败来源不能显示为零。
5. 测试 Key 保存与重启后的调用，检查配置导出里没有 Key；更换 API 地址不应带出旧地址 Key。
6. 测试重新打开、移动应用后重启、退出按钮、登录启动、换皮、屏幕切换。
7. 记录未通过项；只把实际验证的系统/架构加入支持范围。

远端 CI 用来证明“从仓库的文件能够构建和做离线测试”，不能替代上述 UI、认证、钥匙串、签名和真机测试。

## 0.6.1证据修正
0.6.0的固定UserDefaults smoke suite可能读取陈旧状态；CFFIXED_USER_HOME不保证偏好隔离，因此撤回“临时home完全隔离”的声明。本版显式文件偏好替代测试中的cfprefsd，运行文件同样隔离；输出fresh/loaded。反向测试植入气泡默认on/默认额度选择，实际优化GUI必须返回failed和退出码1。smoke会禁止额度查询，负向测试不会联系真实账户。正常默认与单位测试分别验证。

0.6.1本机验证完成：所有离线回归、HTTP模拟、隔离偏好fresh/loaded启动通过；两类默认值mutation均被实际优化GUI拒绝。DSH私有父/子目录、死PID清理与活跃PID保留、Codexstdin桩、所有配置字段均被编码的检查通过。资源及账户数据未进入源码；新增CodexBar fixture完全合成，无真实额度或账号。

最终0.6.1白名单源码目录独立native构建、完整离线回归、本机HTTP模拟及fresh/loaded启动通过；根目录universal含arm64/x86_64，安装版签名通过、CUA确认正常显示及原配置保持气泡关闭。本轮未请求真实模型。调试日志实际检查权限0600。

## 0.6.2偶发偏移调查
静态无闲置巡游/定时位置修改；修复applyConfiguration误调用回复弹跳。之前GUI smoke临时实例确实会显示在默认位置，可能造成用户看到短暂“另一只/移位”的干扰；现在在orderFront之前放到所有可见屏幕之外，且屏幕参数回调不把它移回。smoke仅证明AppKit窗口初始化/资源和配置断言，不等同可见桌面视觉验收。正常安装UI需单独检查。用户所述闲置偏移尚未现场复现；可选本机MotionProbe记录相对位移/动画标签，无截图/正文/绝对坐标。
